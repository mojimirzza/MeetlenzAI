# Innovation Evidence Map — Netherlands Startup Case

This document is an evidence plan, not a legal opinion or immigration guarantee.

| Innovation dimension | MeetLens hypothesis | Evidence currently available | Evidence still needed |
|---|---|---|---|
| New product/service | Meeting Question Intelligence rather than summarization | Working MVP and demo | External user adoption and value validation |
| New technology use | Local semantic inference + structured AI pipeline + human decision gate | Runtime-verified architecture | Real-model benchmark and pilot latency/quality |
| New way of working/organising | Collective question compression with moderator governance | Domain model + workflow | Comparative real-meeting evidence |
| Founder active role | Founder-led product engineering | Repository and execution history | Formal company/role documentation |
| Step-by-step plan | Pilot → evidence → productization | Pilot protocol + roadmap | Company setup milestones and actual execution |
| Scalability | Provider abstraction and production path | Documented architecture | Load/performance tests and deployment evidence |

Official route context should always be verified against the current IND/RVO process before filing. Current IND guidance (updated 8 June 2026) states that the startup must be innovative, the founder must have an active role, a reliable facilitator is required, and a step-by-step plan is assessed by RVO; a positive RVO advice is needed for the residence permit.
